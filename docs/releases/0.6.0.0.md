# MyLSM 0.6.0.0

MyLSM 0.6.0.0 brings binary keys and values, strict UTF-8 access, stable snapshot
scans, and local process coordination together on a single durable storage engine
written in Bend. This release is accepted on Apple Silicon macOS; Linux x86-64
validation remains partial.

## Highlights

- **One engine, two APIs.** `MyLSM.Bytes` stores arbitrary bytes; `MyLSM.Utf8` adds
  strict text encoding and decoding over the same database. Both support durable
  writes, atomic batches, and unsigned lexicographic byte ordering.
- **Incremental scans and stable snapshots.** Range and prefix cursors support
  forward seeking. Owner-managed snapshots retain immutable SST generations until
  their readers release them.
- **Local process coordination.** A database owner serves clients over Unix sockets,
  with bounded connection, request, and transport resources. Typed errors distinguish
  resource limits, stale owner generations, and uncertain commit outcomes.
- **Verified transfer paths.** Consistent backup bundles, validated restore, and
  explicit migration from 0.5 databases publish without replacing existing destinations.
  Migration preserves the source database.
- **Native CLI packaging with Nix.** The installed `mylsm` command includes
  precompiled `demo`, `repl`, and `doctor` support, without requiring Bend or Hub
  downloads at runtime. Development uses pinned tool and dependency revisions.
- **Smaller SST blocks.** Writers now target 4 KiB blocks, avoiding the excessive
  read and decode work caused by filling blocks to the 1 MiB cap. Retired SST files
  are also reclaimed after a successful database open.

## Breaking changes and upgrading

The former top-level String and session APIs and their levelled engine have been
removed. Move callers to `MyLSM.Utf8` or `MyLSM.Bytes`; `Utf8.put`, `Utf8.delete`,
and `Utf8.write_batch` return `Unit`.

New databases use manifest generation 5. Generation 4 remains readable. Databases
from the 0.5 API using storage format 0.4.0.0 / generation 3 require
`migrate_legacy(source, destination)`; normal open does not migrate them. Older
storage generations are unsupported.

The Git tag is `v0.6.0.0`. The library is also published on Bend Hub:

```bend
import mylsm-lsm-store@0.6.0.0/mylsm.bend as MyLSM
```

The published package hash is `0x8f9a5c58059f5db5361cb2eddb73ec7f`.

## Validation

Release checks on macOS arm64 with Bend 2.0.39 recorded:

- **84/84 formal proof modules passing**, with no failures or timeouts.
- **20 owner smokes and the transport oracle unit test passing**, plus the CLI smoke.
- **25/25 engine, crash, backup, migration, and cursor smokes passing**, plus the
  SST round-trip fixture and all three public examples.
- **Five successful samples per write workload**, each with 20,485 writes.
  The `phase3_metrics` median was 20.4 seconds, approximately 1,004 writes/second,
  with 51 ms recovery and 1 ms read p50/p95/p99.
- **Bounded cursor overhead in the measured datasets.** Opening databases with
  16,000–64,000 records used about 3 MiB RSS; scanning 64 items added less than
  the 4 MiB gate allowance.

These are observations from one host. The workload matrix ran with 12% free disk,
below the harness's 15% comparison threshold. Formal laws cover pure decisions;
they do not prove host IO, the filesystem, or dependency primitives.

## Known limitations

- Writes remain approximately **10× slower than the previous String engine** in
  the recorded same-machine comparison: 20.4 seconds versus 1.9 seconds for
  20,485 writes. Moving statistics bookkeeping out of the write path is planned
  for 0.6.1.0.
- There is **no automatic flush or levelled compaction**. Applications must flush
  explicitly to control memtable growth.
- **Linux x86-64 is partially verified.** Proofs and engine smokes passed on an
  earlier candidate, but owner coordination issues and the workload and cursor
  memory checks on the block-size fix remain open for 0.6.0.1.
- File restore currently limits the backup exchange to **64 MiB** and holds the
  exchange and decoded records in memory during validation.
- Owner Unix sockets require native execution; current JavaScript effects do not
  support that transport.
- A lost response after a dispatched write can return `CommitUnknown`. Reopen and
  inspect the database before deciding whether to retry.
