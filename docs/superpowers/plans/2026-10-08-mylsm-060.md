# MyLSM 0.6.0.0 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship MyLSM 0.6.0.0 with explicit UTF-8 and raw-bytes APIs, canonical byte ordering, block-bounded scans and recovery, stable snapshots, coordinated local clients, lock waits, and verified backup/restore/migration.

**Architecture:** Keep one canonical owner process per database. The owner alone holds the OS lock and LSM state; local clients submit bounded requests over a versioned IPC protocol. Both public APIs use one byte-oriented storage engine, while the UTF-8 API is a validating adapter. Cursors pin snapshots over block readers, and backup/migration consume those public contracts.

**Tech Stack:** Bend 2.x, `bend-kit-bytes`, `bend-kit-files`, existing `.bend` pure modules and proofs, paired C/JavaScript host effects, shell smoke/crash fixtures, and existing benchmark tooling.

**Spec:** `docs/superpowers/specs/2026-10-08-mylsm-060-design.md`

**Current verification note (2026-10-09):** The separator index is now written and read by the generation-four byte SST codec, and trusted cursors use bytewise binary search to start at the selected block. The 8,193-block smoke proves a seek for the final key positions the reader at block 8,192; full proofs report `PASS=63 FAIL=0 TIMEOUT=0`. The default `SstCursor.open` still performs its integrity pass from the start before reopening and routing; paths with a previously validated SST use `open.trusted`. Historical ledger entries below that say separators or key seek are unavailable are superseded by this update.

**Route-policy verification update (2026-10-09):** Added witnesses for midpoint selection, completed-search candidate selection, and routing below the first separator. `bend proofs/BlockRoutePolicyProof.bend --verdict` and the complete suite pass (`62/62`). This is an intentional open format task, not a completed seek feature.

**Format-generation ruling (2026-10-11):** 0.6 writes manifest generation 5 and retains generation-4 manifest reads. Generation-addressed immutable SST names alter the published database layout and therefore cannot be mislabeled as generation 4; the generation-4 WAL/SST record encodings remain unchanged and are explicitly identified as component codecs inside a generation-5 database. New databases, flushes, compactions, restore, and migration write generation 5. Cost if wrong: one extra compatibility generation and reader branch; benefit: old 0.6 development databases are not silently reinterpreted or overwritten.

**Generation-addressed SST integration (2026-10-11):** New writes allocate monotonic fixed-width SST identifiers and publish generation-5 manifests only after the uniquely named SST has been synced. ## Global Constraints

- Target release is MyLSM 0.6.0.0; no partial public release of the listed capabilities.
- Keys use unsigned lexicographic byte order everywhere; a shorter prefix sorts first.
- UTF-8 and raw-bytes APIs are distinct public surfaces over one byte-oriented format.
- Filesystem ownership remains exclusive to one process; coordinated clients communicate through local IPC.
- Limits for records, batches, buffers, indexes, queue, connections, cursors, and snapshots are finite and observable.
- Migration source is the durable API 0.5.0.0 and its current 0.4.0.0 storage format; the source is never modified.
- Unsupported host guarantees fail explicitly; no silent fallback that weakens locking, atomic publication, or durability.
- Preserve formal trust boundaries: pure laws and witnesses do not claim to prove host IO, OS locks, or C/JS effects.
- Verification priority: establish pure contracts with laws and witnesses before adding implementation where practical. Use runtime fixtures to verify host effects, integration boundaries, and behavior outside Bend's formal model; test-driven development is not the organizing priority for this release.
- Keep C/JavaScript effects irreducible: one host operation per effect, returning raw results. Bend owns path interpretation, protocol framing, policy, queue behavior, validation, error classification, retries, and state transitions.
- Toolchain review: the repository pins Bend 2.0.36 and the upstream release list identifies 2.0.36 as latest on 2026-10-08. `bend guide` was refreshed from the installed pinned binary to `/tmp/mylsm-bend-guide-2.0.36.txt`; no toolchain change is indicated. The review used the [upstream Bend releases](https://github.com/bendlang/bend/releases).
- Add laws and witnesses for pure byte ordering, format decisions, protocol parsing, queue admission, lifecycle transitions, retention accounting, and migration decisions where they can be expressed as pure functions.
- Never add ticket identifiers to source. Do not add source comments or docstrings without the user's prior approval; retain existing comments in files being changed.
- Check the latest Bend release and refresh `tools/toolchain.json` and `bend guide` before implementation. If the toolchain changes, rerun the complete affected gates.

## Review Focus

- A raw byte value that is not valid UTF-8 must remain readable through the byte API, while the text API returns InvalidUtf8 and leaves its cursor in Error; cover in Task 4.
- A large SSTable whose index exceeds the resident budget must still seek and scan through paged metadata or fail with ResourceLimit before exposing a partial cursor; cover in Tasks 5–6.
- An owner crash between durable commit and response must produce CommitUnknown for the client, preserve atomic recovery, and never trigger an automatic retry; cover in Tasks 9–11.
- A stale IPC endpoint without a live lock must not admit two owners or cause a client to use stale state; cover in Tasks 8–10.
- Long-lived cursors and snapshots that exhaust retention budgets must reject additional retention and preserve already-open readers; cover in Task 7.

The C and JavaScript files above are raw operation bindings, not the place for socket protocol or retry logic. Their Bend wrapper has this shape:

```bend
def socket.read(file: File, max_bytes: U32) -> IO(File & Result<&1, &1, U32 & String, Bytes.Bytes>):
  import "./effs/socket_read.c"
  import "./effs/socket_read.js"
```

The host function performs one read syscall up to `max_bytes` and returns `(handle, raw_result)`; it does not loop, decode a frame, enforce protocol limits, retry, or classify the result. Bend decides whether the bytes complete a header, represent short progress, EOF, malformed input, or timeout. Each foreign binding has one responsibility and matching C/JS behavior on supported runtimes. Unsupported primitives return raw host errors that Bend classifies.

The implicit owner startup path also needs a narrow process-launch primitive. Bend constructs the executable and argument vector from the configured owner command; the effect only starts that process and returns its raw process identifier or host error. A losing concurrent starter observes the winner through the lock/endpoint loop and connects as a client. The owner executable runs `app/mylsm_owner.bend` as a blocking IPC service, so no C/JS thread contains database policy.

## Implementation Shapes

The following snippets pin down the pure decision style and data passed between tasks. They are implementation sketches in the repository's Bend style. Check the pinned bytes-library accessor spelling against `bend guide`; keep the recursion, outcomes, and ownership boundaries shown here.

`bend-kit-bytes` already implements packed unsigned lexicographic comparison, including prefix ordering. The core should expose that comparator through one MyLSM-owned boundary so every engine subsystem shares one order:

```bend
def Bytes.cmp.order(pair: PackedBytes.Bytes & PackedBytes.Bytes & Cmp) -> Cmp:
  match pair:
    case (_, _, order):
      order

def Bytes.cmp(left: PackedBytes.Bytes, right: PackedBytes.Bytes) -> Cmp:
  Bytes.cmp.order(PackedBytes.cmp(left, right))

def Bytes.eq(left: PackedBytes.Bytes, right: PackedBytes.Bytes) -> Bool:
  Cmp.is_eq(Bytes.cmp(left, right))
```

These definitions belong in `src/Keys.bend`. They add no conversion or extra allocation on the key comparison path. Closed fixtures pin empty, prefix, zero-containing, and unsigned boundary cases. The byte library's implementation remains a dependency trust root; do not present those fixtures as a general proof of the library comparator.

Protocol decoding is also pure Bend. The host effect returns bytes only; no C/JS code inspects version tags or lengths:

```bend
type DecodeDecision is Data:
  NeedMore{}
  Reject{error: ProtocolError}
  Request{request: Request, consumed: Nat}

def protocol.decode(input: Bytes.Bytes, max_frame: Nat) -> DecodeDecision:
  match protocol.header(input):
    case HeaderIncomplete{}:
      NeedMore{}
    case HeaderInvalid{error}:
      Reject{error}
    case HeaderValid{version, request_id, payload_len}:
      match protocol.validate_header(version, payload_len, max_frame):
        case Fail{error}:
          Reject{error}
        case Done{Unit{}}:
          protocol.decode_payload(input, request_id, payload_len)
```

Add laws for `NeedMore` on every strict prefix of a valid frame, rejection before payload allocation for an oversized frame, and encode/decode agreement for valid requests. The socket reader itself does not decide how many retries to make: an owner state machine in Bend interprets short reads and calls the next raw read operation.

The owner queue and retained-file decisions follow the same pattern: pure functions compute `Accepted(queue) | QueueFull | ResourceLimit` and `Retain(files) | Reclaim(files)` from explicit state; IO tasks execute only the resulting writes, reads, rename, unlink, lock, and socket operations. For example, queue admission receives the current count, encoded bytes, limits, and request size, and returns either the updated queue or a rejection. It does not open a socket or allocate an unbounded buffer. This gives laws a precise decision boundary and keeps host effects narrow.

Queue policy should have a testable pure signature before it is connected to sockets:

```bend
type QueueDecision is Data:
  QueueAccepted{count: Nat, bytes: Nat}
  QueueFull{}
  RequestTooLarge{}

def queue.admit(count: Nat, queued_bytes: Nat, request_bytes: Nat,
    max_count: Nat, max_bytes: Nat) -> QueueDecision:
  match Nat.is_lt(max_bytes, request_bytes):
    case True{}:
      RequestTooLarge{}
    case False{}:
      match Nat.is_lt(max_count, Nat.add(count, 1n)):
        case True{}:
          QueueFull{}
        case False{}:
          match Nat.is_lt(max_bytes, Nat.add(queued_bytes, request_bytes)):
            case True{}:
              QueueFull{}
            case False{}:
              QueueAccepted{Nat.add(count, 1n), Nat.add(queued_bytes, request_bytes)}
```

Add a separate preflight decision for a single request larger than `max_bytes` so it returns `RequestTooLarge`, while temporary saturation returns `QueueFull`. The policy law proves rejected admission leaves the original queue state unchanged; the host layer only waits for queue capacity or returns the decision.

The cursor carries explicit lifecycle state so callers cannot accidentally reuse a closed or failed reader:

```bend
type CursorState is Data:
  CursorReady{snapshot: Snapshot, sources: List<&2, Source>, pending: Maybe<&2, Entry>}
  CursorEnded{}
  CursorFailed{error: Error}
  CursorClosed{}

type CursorStep is Data:
  CursorItem{entry: Entry, state: CursorState}
  CursorEnd{state: CursorState}
  CursorError{error: Error, state: CursorState}

def cursor.next(state: CursorState) -> CursorStep:
  match state:
    case CursorReady{snapshot, sources, pending}:
      cursor.merge_next(snapshot, sources, pending)
    case CursorEnded{}:
      CursorEnd{CursorEnded{}}
    case CursorFailed{error}:
      CursorError{error, CursorFailed{error}}
    case CursorClosed{}:
      CursorError{ClosedError{}, CursorClosed{}}
```

Implement `cursor.merge_next` as a pure source-selection transition over one candidate head per source. The IO wrapper fills a missing candidate by reading one block entry, then invokes that transition; it does not choose key precedence or suppress tombstones itself. Add a law that End, Error, and Closed are terminal states and a witness for duplicate-key newest-wins behavior.

## Interfaces Shared Between Tasks

These are plan-level contracts. Exact Bend kind annotations should follow existing ownership conventions when implemented.

- `Keys.Bytes.cmp(left, right) -> Cmp` and `Keys.Bytes.eq(left, right) -> Bool` define canonical ordering and equality. Existing String comparison remains available only for unrelated text and the adapter surface.
- Internal byte entries store `key: Bytes.Bytes` and `val: Maybe<Bytes.Bytes>`. In Bend these buffers are affine `Type` values rather than unrestricted `Data`: lookups therefore return the updated table alongside a result and clone only a returned value when the table must retain its copy. WAL mutations, SST entries, Bloom inputs, and range bounds use the same byte type.
- Public API is partitioned as `Utf8.*` and `Bytes.*`. Both expose create/open, get, put, delete, write_batch, scan, snapshot, stats, backup/export, and close where the operation makes sense. `Utf8.*` converts only at its boundary and returns `InvalidUtf8` on invalid decoded data.
- A cursor is an owned resource with `seek(lower_bound)`, `next() -> Item | End | Error`, and `close()`. It pins one snapshot and bounded reader state. A text cursor becomes terminal Error on an invalid UTF-8 item.
- A snapshot identifies an immutable MemTable root set plus an immutable SSTable file-set generation. File reclamation waits until the final reference is released.
- IPC requests carry protocol version, request identifier, bounded payload length, and typed operation. Replies carry the same identifier and a typed result. Mutation retries are never automatic.
- The owner queue is bounded by item count and encoded bytes. Queue-full behavior is backpressure/timeout, never unbounded allocation.
