# LSM Key-Value Store Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build a durable, write-optimized tiered LSM key-value store in Bend 2, with every behavior covered by a proven law.

**Architecture:** Generic ordered-key core (`String` first) with MemTable + checksummed WAL + tiered SSTables + Manifest + merge iterator; writes never read, commits ack only after fsync, flush/compaction run in background.

**Tech Stack:** Bend 2.0.4 (minimum floor), Base library only (no extra packages, no foreign C/JS effects), git.

**Spec:** `docs/superpowers/specs/2026-09-17-lsm-bend-design.md`

## Global Constraints

- Bend 2.0.4 is the version floor (`bend --version` must report 2.0.4+ before any task).
- No `@unsafe` def anywhere in the repo — core, proofs, and harness alike.
- Affine by default; `+` annotations only on `Data` values where sharing is needed.
- All recursion structurally decreasing or `Nat`-fuel-bounded.
- Every commit must pass `./proofs/run.sh` ("All terms check."); a red gate blocks the commit.
- One fsync per batch commit (group commit); never one sync per key.
- Compaction fan-in default T = 4 tables per level; MemTable entry cap MEMTABLE_ENTRY_CAP = 4096 (both tunable only with a re-recorded benchmark baseline).
- Host effects limited to Base `File`/`IO` operations; proofs stay in pure Bend.
- Array indexes explicitly bounds-checked against known size; wraparound is never load-bearing; no `Array.clone` aliasing.

function fsync(path) {
  const fs = require("fs");
  const name = io_bytes(path);
  try {
    const fd = fs.openSync(Buffer.from(name), "r+");
    fs.fsyncSync(fd);
    fs.closeSync(fd);
    return io_done({ $: "Unit" });
  } catch (e) {
    return io_fail(Math.abs(e.errno ?? 5));
  }
}

```python
# src/MemTable.bend
import Base
import ./Keys.bend as Keys

type Entry is Data:
  Entry{key: String, val: Maybe<String>}

type MemTable is Data:
  MT{entries: List<Entry>}

def empty() -> MemTable:
  MT{Nil{}}

def put(t: MemTable, k: String, v: String) -> MemTable:
  insert_sorted(t, Entry{k, Some{v}})

def del(t: MemTable, k: String) -> MemTable:
  insert_sorted(t, Entry{k, None{}})

def get(t: MemTable, k: String) -> Maybe<String>:
  match t:
    case MT{entries}:
      scan_get(entries, k)

def count(t: MemTable) -> Nat:
  match t:
    case MT{entries}:
      List.length(&2, Entry, entries)
```

`insert_sorted` keeps `entries` strictly ordered by `Keys.cmp`, replacing any existing entry with the same key; `scan_get` walks the list, returning the entry's `val` (`None{}` = tombstone = not-found) on key match and `None{}` when passing the key's sort position. Prove `mt_ryw`/`mt_del` by case analysis on the insertion walk in `proofs/*Proof.bend`.

law bloom_safe:
  for e: List<MemTable.Entry>
